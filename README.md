# 在路上 · 求职 / 申博进度追踪

> 我们准备着深深地领受 / 那些意想不到的奇迹 —— 冯至《十四行集》
> *Live the questions now.* —— Rainer Maria Rilke

页面顶部是上下对齐的三栏：

- **深色一行**：「在路上」名字和图标 + 秋招 / 申博切换；本页流程标签；当前标签页的操作按钮（添加投递、添加活动等），最右端是账号头像（用户名首字，未登录时显示「登录」）。
- **浅色一行**：
  - 三栏开头的标题字号、间距一致，下面的内容因此对齐。
  - 左栏：日期和星期、本页题记（秋招页冯至，申博页里尔克），以及「📥 收件箱」「🔔 提醒」「⬇ 备份」「⬆ 导入」四个按钮。需要备份时，按钮下面会多出一行提示。
  - 中栏：「用户名，今天是你秋招 / 申博的第 N 天」（从最早一条记录算起；未登录时不带用户名，点用户名打开账号设置），下面是竖排的统计数字（秋招：已投递 / 面试中 / 已录用；申博：已套磁 / 有回复 / 网申中），字号和题记相同，只有数字加粗。
  - 右栏：按时段变化的问候语（6–13 点、13–18 点、18–22 点、22 点以后各一句）、日程（今天 / 明天，未来 7 天默认折叠）和下面的「📅 活动」入口，日程右边是「每日一画」（见下）。

顶部整块（两行）都用宋体系衬线体；下面的看板、列表、表单用无衬线体（Windows 上是 Segoe UI + 微软雅黑，Mac 上是系统字体 + 苹方）。页面一直开着时，问候语、日期和日程每 5 分钟刷新一次。窄于 1100px 时三栏改为上下排列，每日一画隐藏。衬线字体使用系统自带的宋体系字体，不从网络加载。

**🖼 每日一画**：不设固定画单。每个页面有一组主题词（秋招页偏「路」：road、river、journey、harbor…；申博页偏「书斋」：reading、moon、scholar、letter…），每天按日期轮到一个词，在[克利夫兰艺术博物馆开放数据](https://openaccess-api.clevelandart.org/)的公有领域（CC0）馆藏里按标题搜油画，再按日期挑出一幅，同一个词下次轮到时会换一幅。一天只请求一次，结果缓存在本地；当天取不到时继续显示上一次的画。主界面只显示图片，悬停显示资料卡，点击放大并可以跳到博物馆页面。图片由浏览器直接向博物馆请求，不经过本项目的服务器，不需要登录。

两个独立的单文件追踪工具，分别服务秋招求职（`index.html`）和博士申请（`phd.html`）两条时间线。两者布局一致、色调区分（秋招森林绿 / 申博墨蓝），顶部栏最左边的「📋 秋招 | 🎓 申博」开关用来切换，但数据、逻辑完全独立，互不影响——因为求职和申博的信息结构差异较大（前者是"公司→职位"的层级关系，后者是"导师↔项目"的多对多关系），硬塞进同一套数据模型只会让表单里堆满两边都用不上的字段。

## `index.html` · 秋招求职追踪

用来记录投递进度，按公司关注、具体职位、实际投递三个层级组织信息，方便回顾自己实际在关注哪些行业和岗位方向。

### 三层结构

一次求职决策通常要经历"知道公司→锁定职位→实际投递"这几个由模糊到明确的阶段，所以数据也拆成对应的三层，顶部导航栏按这个顺序排列并用箭头连接：**🏢 公司关注 › 📌 待投岗位 › 📋 投递追踪**：

- **🏢 公司关注**：只知道公司值得盯着，还没确定具体岗位。记公司名、行业、公告/官网链接、备注即可。公司卡片可以展开查看已经派生出的具体职位——不管这些职位是还在"待投岗位"阶段，还是已经进了"投递追踪"，都会一起显示（后者会带上真实的投递状态标签），方便一眼看出这家公司到底跟到哪一步了，避免同一家公司重复投递。列表按"🔍 待筛选"（还没有任何关联职位）和"✅ 已有职位在跟进"分成两个折叠区块。关注公司既可以在这一页直接添加，也可以在添加待投岗位/投递记录时顺手加上（见下）。在这里修改公司名称时，已关联职位上的公司名会一起更新。
- **📌 待投岗位**：已经锁定的具体职位，尚未投递。每条记录标注：
  - 关注类型——**计划投递**（近期打算投）或 **长期关注**（感兴趣但暂不投，可选填原因，如能力/经验暂时不够、岗位尚未开放申请等）
  - 职位类型——全职/实习/应届生项目/科研/兼职/其他
  - 截止日期——支持标记**滚动招聘（Rolling Basis）**，即没有固定截止日期的岗位
  - 优先级、薪资、地点；默认按优先级排序
- **📋 投递追踪**：已经投出的申请。看板视图是按状态（已投递/已查看/面试中/已录用/已拒绝）分区的折叠式区块——有记录的默认展开、没有的收起成一行，避免"已投递"这类数量多的状态把页面拉得很长；区块内支持拖拽调整卡片顺序，跨区块拖拽（哪怕目标是收起状态）可以改变投递状态。每条记录可以记录完整的流程时间轴（笔试、面试、Offer Call 等环节及日期），每个环节能一键导出 `.ics` 日历文件（标题格式"公司-职位-环节"），导入手机日历后可以设提醒，间接实现截止日期提醒到手机。

不管在"待投岗位"还是"投递追踪"填公司名，输入时如果已有同名记录（不论在哪一层），都会实时提示"已有N条已投递/待投递记录"，提醒你可能要重复投了。

**公司名和关注公司的关联**：两层表单里只有一个"公司名称"输入框（手动输入或自动提取都填在这里），输入时会下拉提示已关注的公司。保存时按名称（忽略大小写和首尾空格）自动匹配关注公司；如果没有匹配到，输入框下方有"同时加入关注公司"的勾选项（新增时默认勾选，编辑旧记录时默认不勾），勾上就会顺手新建一条关注公司（投递记录的行业也会带过去）。早期没有关联字段的旧记录，只要公司名一致也会在关注公司页里归到对应公司下。

数据存储在浏览器 `localStorage`（`jt4` 投递追踪 / `jt4_toApply` 待投递 / `jt4_companies` 公司关注 / `jt4_events` 活动；登录后键名前面加 `u:用户名:`），不上传到任何服务器，换浏览器或清缓存会丢失。见下方「💾 备份」。

配套的 `api/extract.js` 是一个无状态的 Vercel Serverless Function，把粘贴的职位页面文字（或 URL）转发给 DeepSeek API，自动提取公司、职位、行业、职位类型、来源渠道，用于表单里的"自动填写"功能。谁的额度来付这次调用，见下方「✨ 自动填写的两个通道」。

### `capture.html` · 手机端速记收件箱

解决"手机上刷到小红书/公众号的秋招/申博信息，没空仔细研究也不在电脑旁"的场景：`capture.html` 是一个极简的手机端网页（纯 HTML/JS，不加载 React，追求打开即用），顶部有"📋 秋招 / 🎓 申博"切换（记住上次选的），粘贴文字或帖子链接、点一下就存进对应的云端收件箱。

- 秋招那份收件箱回 `index.html`，点顶部导航栏的"📥 收件箱"（全局入口，任意 tab 下都能点）。单条内容会自动跑一遍 `api/extract.js` 的 AI 提取、显示"推测：公司名 · 行业"，可以一键"转成关注公司"（如果内容里明确提到了官网/投递链接也会优先用那个而不是原始帖子链接）或者直接忽略。如果粘贴的是**多行文本**（比如手动抄下来的一份秋招公司清单，一行一个公司名），会识别成"看起来是一份清单"、跳过 AI 提取，改为提供"批量拆分成 N 个"——一键把每一行拆成一条独立的"待筛选"关注公司记录，不猜行业/链接，等你自己后续研究。
- 申博那份收件箱回 `phd.html`，同样是顶部导航栏的全局"📥 收件箱"，用 `api/extract-phd.js` 提取，显示"推测：学校 · 项目"，每条可以"转成网申项目"或忽略。这边目前只支持转成网申项目，不支持转成套磁记录——套磁记录本来就基本是在电脑上直接录入的场景，没有额外做手机速记的必要。

收件箱存在云端（Vercel KV），因为要在手机和电脑两端共享，所以**需要登录**（见下方「👤 账号」）。手机上在 `capture.html` 底部展开「登录」，用同一个账号登录一次即可；注册请在电脑上用邀请码完成。每个账号的收件箱互相独立。

三个接口：`api/inbox-add.js`（写入，`capture.html` 调用）、`api/inbox-list.js`（电脑端拉取列表）、`api/inbox-delete.js`（转换或忽略后从收件箱移除）。三个接口都接受一个 `target` 参数（`job` 或 `phd`，默认 `job`），秋招和申博的收件箱数据完全不会串。

**国内不开 VPN 怎么用**：`*.vercel.app` 在国内被屏蔽。仓库里的 `netlify.toml` 让同一个仓库也能部署到 Netlify：页面由 Netlify 提供，`/api/*` 原样转发给 Vercel 上的接口，所以账号、收件箱、提醒、日历都是同一份。注意 `localStorage` 按网址区分：在新网址上要重新登录一次；投递、套磁记录也跟着网址走，**每个人固定用一个网址**即可（需要换网址时，用「备份 / 导入」搬过去）。

**使用提示**：小红书这类 App 的"分享"按钮很多是自己定制的面板，不接入 iOS 系统分享，所以没法通过快捷指令（Shortcuts）自动投递到收件箱，只能靠 `capture.html` 手动复制粘贴。想让 AI 提取效果更好，尽量连**帖子文字**一起复制粘贴进去（而不是只存链接）——服务器抓取小红书链接本身大概率因为反爬/前端动态加载拿不到真实内容。图文帖（比如秋招汇总表格截图）建议只存帖子链接，回电脑自己点进去筛选，不做图片文字提取。

## `phd.html` · 博士申请追踪

用来记录套磁进度和网申项目进度，两者是多对多关系（一个导师可能关联多个网申项目，一个网申项目也可能关联多个联系过的导师），所以做成两个独立列表、互相关联，而不是像秋招那边那样做严格的层级结构：

- **🧑‍🏫 套磁记录**：导师姓名、所在院校、研究方向（多关键词标签，见下）、套磁进度（待发送→已发送→已跟进→已回复→已约谈→成功/未成功）、沟通反馈时间轴（自由记录日期+内容，不设固定环节名称，因为套磁反馈内容因人而异）、可多选关联网申项目。表单同样支持"自动提取"——配套的 `api/extract-phd-professor.js` 是专门为导师个人主页文字设计的提示词（提取姓名/院校/研究方向关键词数组），同样需要 `DEEPSEEK_API_KEY`。
  - **研究方向标签**：因为一个导师的研究方向通常由多个独立关键词组成（如"机器学习"+"计算机视觉"），做成类似 Notion 多选属性的标签输入——不是自由文本框，而是一个会在全局"标签池"里逐渐累加的选择器：输入关键词回车即可创建新标签，之后填别的导师时可以直接从池子里搜索、点选已有标签，不用每次重打一遍。标签池独立存在 `localStorage`（`phd_research_tags`），一旦创建即永久保留在池子里（哪怕后来把用到它的导师都删了），跟 Notion 的多选属性行为一致。自动提取信息时识别出的研究方向关键词也会自动汇入标签池。
- **🎓 网申项目**：学校、项目/院系、申请批次、截止日期（同样支持标记**滚动招生**，即无固定截止日期）、网申状态（材料准备中→已提交→审核/面试中→已录取/Waitlist/未录取，Waitlist 单独列出是因为它和"未录取"是完全不同的状态）。卡片展开会反向显示关联的导师，不需要两头分别维护。表单同样支持"自动提取"——配套的 `api/extract-phd.js` 是专门为项目页面文字设计的提示词（提取学校/项目/批次/截止日期，跟 `api/extract.js` 面向职位JD的字段不一样），同样需要 `DEEPSEEK_API_KEY`。

两个标签页都可以在「卡片 / 列表」之间切换（切换状态两页共用）：列表视图是一行一条的表格，套磁记录显示导师、院校、研究方向、状态、最新沟通、关联项目、备注；网申项目显示学校、项目、批次、状态、截止日期（7 天内标红、过期置灰）、关联导师、备注，方便一眼横向对比。列表视图每行前有勾选框（表头可全选当前筛选结果），勾选后顶部出现批量操作栏：套磁记录可批量改状态 / 发送日期 / 跟进日期，网申项目可批量改状态 / 批次 / 截止日期，留空的字段不改；也可以批量删除。

数据存储在 `localStorage` 的 `phd_professors` / `phd_applications` / `phd_research_tags`（研究方向标签池）/ `phd_events`（活动），与秋招追踪器的存储完全独立，互不影响。目前还没有做研究计划模板库（相似方向导师共用的研究计划模板管理），后续视需要再加。

## 💾 备份

投递、套磁这些记录只存在当前浏览器里（登录后按账号分开，见下方「👤 账号」），**不跨设备**。备份 / 导入既用来防丢，也是在设备、浏览器、网址之间迁移记录的唯一方式。两个页面左栏都有「⬇ 备份」和「⬆ 导入」：

- **备份**：把本页的全部数据存成一个 JSON 文件（秋招页：投递、待投岗位、关注公司、活动；申博页：套磁、网申、研究方向标签池、活动），文件名形如 `在路上-秋招备份-2026-10-12.json`。
- **导入**：按记录 id 合并，只新增本地没有的记录，已有的不会被覆盖；导入前会列出每一类将新增几条，确认后才写入。秋招页的备份不能导入到申博页，反过来也一样。旧版只含投递记录的导出文件也能导入。
- **提醒**：页面有数据、但从来没备份过，或者距上次备份满 14 天（`BACKUP_REMIND_DAYS`）时，按钮下面会显示一行「距上次备份已经 N 天 · 现在备份」。

以下情况会丢数据：清除浏览器数据、使用无痕模式、iPhone / Mac 的 Safari 连续 7 天没打开这个网站（苹果的隐私策略会清掉网站存储；把网页「添加到主屏幕」可以大大降低这种风险）。换浏览器或换设备不会丢，但那边看不到，需要用备份文件导入过去。

## 👤 账号

同一个部署可以给多个人用：凭**邀请码注册**，之后用**用户名 + 密码**登录。入口是深色导航行最右端的账号头像（未登录时是「登录」），或者中栏标题里的用户名，打开「👤 账号」面板：登录 / 注册、站长管理、自动填写设置。

- **云端那部分**：收件箱、提醒同步、每日邮件、日历订阅都按账号分开存，互相看不到，在任何网址、任何设备上登录都是同一份。
- **本地记录**（投递、待投、关注公司、套磁、网申、活动、研究方向标签、个人 DeepSeek key）**不会上传，也不跨设备**，只存在当前浏览器里，但会按账号分开：同一个浏览器上登录不同账号，各看各的；登录、退出或切换账号后页面会自动刷新。未登录时用的是另一份「未登录」的记录。
  - 第一次在某个浏览器上登录一个账号时，如果这里有未登录时记下的记录、而这个账号在这里还没有记录，会询问是否把它们**移到**这个账号下。选「取消」，这个账号就从空白开始。
  - **换设备、换浏览器或换网址**（比如从 Vercel 网址换到 Netlify 网址）时，记录不会自动跟过去，需要**手动迁移**：在原来的地方点「⬇ 备份」，到新的地方登录同一个账号，再点「⬆ 导入」。秋招页和申博页各做一次。
- **站长**：注册时邀请码填部署环境变量 `INBOX_SECRET` 的值，就成为站长账号（只能注册一次）。站长在面板里展开「🔑 站长：邀请码与用户」，可以生成一次性邀请码、作废没用的码、查看用户，并给每个用户开关 AI 系统额度。
- **旧密钥仍然有效**：在账号功能上线前，各页面和 `capture.html` 用 `INBOX_SECRET` 直接访问。这把密钥现在依然被当作站长身份，所以旧设备和已经订阅的日历不用重新设置。站长的数据继续使用原来的存储键（`inbox`、`reminders_job` 等），没有做过迁移；其他用户的数据存成 `u:用户名:inbox` 这类键。
- **安全**：密码只存 scrypt 哈希；登录后服务器发一个令牌（有效期一年），存在浏览器原来放密钥的位置（`jt4_inbox_key`），所有云端接口都靠它认人。日历订阅用的是另一个单独的「日历令牌」，所以把订阅链接给了别人，对方也拿不到登录身份。
- 接口：`api/account.js`（注册、登录、退出、邮件设置、站长管理），公共逻辑在 `api/_lib.js`（文件名以下划线开头，Vercel 不会把它部署成接口）。

## ✨ 自动填写的两个通道

表单和收件箱里的「自动填写」要调用 DeepSeek，费用由下面两种方式之一承担。在「👤 账号」面板的「✨ 自动填写（AI）」里查看或设置：

| 通道 | 谁付费 | 条件 |
|---|---|---|
| **自己的 DeepSeek key** | 使用者自己 | 在面板里粘贴 key 即可，不需要登录。key 只存在这个浏览器里（`jt4_deepseek_key`），每次请求时转交给 DeepSeek，服务器不保存 |
| **系统额度** | 站长（部署环境变量 `DEEPSEEK_API_KEY`） | 需要登录。站长本人不限次数；其他用户要站长在管理面板里开通，每人每天最多 `AI_DAILY_LIMIT` 次（默认 30，按北京时间计日） |

两种都不满足时，自动填写会提示去登录、找站长开通，或者填自己的 key。DeepSeek 返回的常见错误（key 不对、余额不足、请求太频繁）会翻译成中文显示。申请 key：在 [DeepSeek 开放平台](https://platform.deepseek.com) 注册并充值，然后创建 API key。

## 📅 活动（宣讲会 / 网络研讨会 / Open Day…）

两个页面各有一个「📅 活动」标签页，数据分开存（`jt4_events` / `phd_events`），因为两边要记的信息不一样：秋招活动关联公司，类型是宣讲会、Insight Day、Networking 等；申博活动关联学校和网申项目，类型是项目宣讲、招生答疑、学术讲座等。

- **录入**：添加活动时粘贴宣传链接、文章文字或报名成功邮件正文，点「自动填写」。配套的 `api/extract-event.js` 会提取活动名、主办方、日期、起止时间、**时区**、参会链接、报名链接、报名截止（同样需要 `DEEPSEEK_API_KEY`）。手机上可以在 `capture.html` 选「📅 活动」先存进收件箱，回电脑在收件箱点「转成活动」；普通收件箱条目也有「转成活动」按钮。
- **时区**：活动时间按原时区保存（如英国时间 14:00），页面、提醒邮件和日历都换算成你自己设备的本地时间显示，夏令时也会自动处理。
- **状态**：想参加 → 已报名 → 已参加 / 错过了。卡片上有快捷按钮；标成「已参加」后可以记「收获 / 要点」。
- **提醒**：「已报名」的活动在**前一天**出现在提醒邮件里，并同步到订阅日历（有结束时间就按实际时长显示，带参会链接）。「想参加」且填了报名截止的，截止前一天和当天提醒。活动相关的日历条目都**不设闹钟**。

## 🔔 提醒：每日邮件 + 日历订阅

解决"忘了 follow up 套磁信""记错笔试时间"这类问题。

**页面布局**：「🔔 提醒」按钮（今天到期 / 逾期的数量，同步出错时显示 ⚠️）打开「🔔 提醒」面板：同步状态、每日邮件设置和测试、日历订阅（未登录时提示先去登录）。顶部右栏是 **🗓 日程**：「今天 / 明天」（含逾期未处理的跟进、待投提醒，标红），「未来 7 天」默认折叠；点本页的条目直接打开对应记录。另一个页面的日程也会出现在这里，但只用浅灰小字显示「这段时间被占了」，不可点——它读的是另一个页面最近一次打开时缓存在本地的 `agenda_job` / `agenda_phd`（不显示另一边逾期的待办）。窄屏下标签栏可以横向滑动，日程两栏会改成上下排列。

**会提醒什么**

| 来源 | 什么时候提醒 |
|---|---|
| 套磁记录，状态「已发送」 | 发送日期 + 5 天提醒第一次跟进 |
| 套磁记录，状态「已跟进」 | 最近一次跟进日期 + 2 天提醒再次跟进 |
| 投递追踪的流程环节（笔试、面试等） | 前一天 + 当天（已拒绝的投递不提醒） |
| 待投岗位（计划投递）、网申项目（材料准备中）的截止日期 | 前 7 天、前 1 天、当天 |
| 待投岗位的「⏰ 提醒我」日期（适合没有确定截止日期的日常实习、滚动招聘） | 当天起每天重复，直到标记已投、删除或改日期；卡片上可一键「推后 4 天」。勾选「滚动招聘」时自动填成 4 天后（`ROLLING_REMIND_DAYS`），可手动改或清除 |

套磁跟进的提醒到期后**每天重复**，直到状态变化（点卡片上的「✓ 已跟进」会把状态改成已跟进、记下今天的日期并写一条沟通记录，然后开始下一轮 2 天的计时）。间隔天数是 `phd.html` 里的 `FOLLOWUP_FIRST_DAYS` / `FOLLOWUP_AGAIN_DAYS` 两个常量。套磁表单里状态改成「已发送 / 已跟进」时会自动把对应日期填成今天，可以手动改；没填发送日期的记录不会提醒，卡片上会提示。

**怎么做到的**：数据仍然只在本机 `localStorage`，但登录后，每次改动页面都会把算好的"提醒条目"（标题、日期、提醒日，不含其余字段）同步到 Vercel KV（按账号分开存，接口 `api/reminders-sync.js`）。没登录就不同步。

**每日邮件：每个人用自己的 Resend**。在面板的「📧 每日邮件」里按提示操作：

1. 打开 [resend.com](https://resend.com)，**用你想收提醒的邮箱**注册。没有验证自己的域名时，Resend 只能从 `onboarding@resend.dev` 发信给注册它的那个邮箱，所以收信邮箱不能另外随便填。
2. 在 API Keys 里新建一个 key，名字随便填，权限选 **Sending access**（只能发信）。
3. 把 key 和邮箱填进面板、保存，点「发一封测试邮件」。失败时会显示中文原因，比如「收信邮箱必须是你注册 Resend 时用的那个邮箱」。

Resend key 会用 AES-GCM 加密后存进 KV（密钥由 `INBOX_SECRET` 派生），面板里只显示前后几位。因为每天早上是服务器替你发信，key 必须存在服务器上；站长技术上能解密，介意的话随时可以在 Resend 后台删除这个 key。站长如果没在面板里填，就沿用部署环境变量 `RESEND_API_KEY` / `REMIND_EMAIL_TO`。

- **`api/remind.js`**：Vercel Cron 每天 UTC 0 点（北京时间 8 点）调用一次（`vercel.json`），逐个账号检查，有到期事项就用这个账号自己的 Resend 发一封汇总邮件，没有就不发。邮件里的链接（打开追踪页、订阅日历）指向这个用户平时打开网站用的网址（同步提醒时记下的，Vercel 或 Netlify），所以国内用户点得开。手动调用只针对当前登录的账号：`/api/remind?key=登录令牌` 立即检查并发信；加 `&dry=1` 只在网页上预览不发信；加 `&date=2026-10-15` 模拟某一天；加 `&test=1` 即使没有到期事项也发一封。提醒面板里有「预览今天的邮件」「发一封测试邮件」两个按钮。
- **`api/calendar.js`**：每个账号一个日历订阅地址，形如 `https://你的域名/api/calendar/日历令牌.ics`，秋招和申博的提醒都在里面。面板里分两种复制：
  - **iPhone / Mac**：`webcal://` 开头，点提醒邮件底部的「订阅提醒日历」也行。订阅时要**关闭「移除提醒」**，否则笔试面试的闹钟不会响。大约每小时刷新一次。
  - **Outlook / Google 日历**：`https://` 开头。Outlook 选「添加日历 → 从 Internet 订阅」，Google 日历选「其他日历 ＋ → 通过网址添加」。这两家**不执行闹钟**，只显示日程，而且几小时到一天才刷新一次。新版 Outlook 不接受带 `?key=` 的旧式地址，所以改成了以 `.ics` 结尾。

  **只有投递追踪时间轴里的环节（笔试、面试等，错过就没法补救）带闹钟**：有具体时间的，前一天同一时间 + 开始前 2 小时；没填时间的，前一天和当天 9:00。截止日期、套磁跟进、待投岗位提醒、活动都只显示在日历和邮件里，不响。时间按北京时间标注（带 `TZID=Asia/Shanghai`）。旧的 `?key=INBOX_SECRET` 地址仍然可用。

**需要额外配置的环境变量**

- `CRON_SECRET`：随便设一串字符串，Vercel 定时任务调用时会自动带上，防止别人触发发信。
- 站长可选：`RESEND_API_KEY` + `REMIND_EMAIL_TO`（不想在面板里填时，站长自己的邮件用这组）、`REMIND_EMAIL_FROM`（验证域名后自定义发件人）。
- 可选：`REMIND_TZ`（判断"今天"用的时区，默认 `Asia/Shanghai`；改时区的话 `vercel.json` 里的发送时间也要跟着改）、`SITE_URL`（用户还没同步过提醒、不知道他用哪个网址时，邮件链接用这个地址，默认取请求域名）。

## `resume.html` · 简历定制工作流

> 目前 `index.html` / `phd.html` 里已经不再放这个工具的入口，代码保留在仓库里，需要时双击根目录的 `start-resume-tool.bat` 打开。

给 `resume-workflow/`（本地 DeepSeek API 简历定制脚本）配的网页前端：四步走——JD 拆解 → 定制方案 → JSON 修改指令 → 生成定制 `.docx`，每一步的产物都能直接在网页里编辑、保存后再继续，不用去改文件；也支持一键连续生成全部四步。

**这是一个完全本地化的个人工具，不是"部署到 Vercel 就能给任何人用"的功能**：

- 页面本身（`resume.html`）不管是本地打开、还是通过部署的 Vercel 线上站点打开，所有数据请求都写死发往 `http://127.0.0.1:5055`——不管从哪里加载这个页面，真正起作用的永远是**你自己电脑上**跑着的本地服务（`resume-workflow/server/app.py`，用根目录的 `start-resume-tool.bat` 启动）。
- 简历文件、生成的 JD 拆解/方案/JSON 指令/定制简历，全部存在本机的 `resume-workflow/input/` `resume-workflow/output/` 目录，从不上传到任何服务器（包括 Vercel、GitHub），不会随链接分享给别人，也不会在别的设备上出现。
- 为了能在 Vercel 线上页面上一键唤起本地服务（不用手动去文件夹找 `.bat` 双击），额外注册了一个 `resumeworkflow://` 自定义协议（`resume-workflow/register-protocol.ps1`），只写入**当前 Windows 用户**的注册表，只对这台电脑这个账号生效。

## 技术实现

- `index.html` / `phd.html` 是纯静态单文件：React 18 + Babel Standalone，均通过 CDN 引入，无需构建步骤，直接用浏览器打开即可运行，共享同一套布局和组件样式（卡片、弹窗动效），只换主色调。两个页面用顶部的「秋招 | 申博」开关切换；除了日程卡片会读取对方缓存的日程条目外，不共享任何数据。
- `capture.html` 是纯 vanilla HTML/JS，不引入任何框架，专门为手机端弱网/快速打开优化。
- `api/` 下共 11 个 Serverless Function（Vercel 免费版上限 12 个），公共逻辑放在不会被部署成接口的 `api/_lib.js`。
- 环境变量汇总：`KV_REST_API_URL` + `KV_REST_API_TOKEN`（云端存储，关联数据库后自动生成）、`INBOX_SECRET`（站长注册用的邀请码 + 旧密钥 + 加密 Resend key 的密钥来源，自己设定，**设好后不要再改**，否则已保存的 Resend key 会解不开）、`CRON_SECRET`（每日邮件）、`DEEPSEEK_API_KEY`（系统额度，可选）、`AI_DAILY_LIMIT`（可选，默认 30）。站长邮件的可选项见上方「提醒」一节。

## 使用

直接用浏览器打开 `index.html`（秋招）或 `phd.html`（申博）即可使用，两边顶部的开关可以互相切换。登录、收件箱、自动填写、提醒都需要项目部署在支持 Serverless Function 的平台（如 Vercel）才能生效，本地直接打开文件时会自动降级为手动填写、提示收件箱加载失败。

6. **手机速记（可选）**：手机上打开同一个网址下的 `/capture.html`，在底部登录。

## 自己部署一份

代码里没有写死任何跟原作者账号绑定的东西，谁 fork 这个仓库都能部署出一套完全独立的实例，互不影响、不会用到别人的 API 额度或收件箱数据：

1. Fork 这个仓库到自己的 GitHub 账号。
2. 去 Vercel 导入这个仓库直接部署。零配置也能跑，只是账号、收件箱、提醒和系统额度的自动填写会失效（靠 localStorage 的功能完全不受影响，自己的 DeepSeek key 也照样能用）。
3. 想要完整功能，在自己 Vercel 项目的 Environment Variables 里配：
   - `KV_REST_API_URL` / `KV_REST_API_TOKEN`：在 Vercel 项目的 Storage 里关联一个 **Upstash for Redis** 数据库，这两个会自动生成，不用手填
   - `INBOX_SECRET`：自己定一串足够长的随机字符串。部署好后，用它作为邀请码注册，你就是站长
   - `CRON_SECRET`：随便一串字符串，每日邮件需要
   - `DEEPSEEK_API_KEY`（可选）：想给自己或朋友提供系统额度时再配
4. 改完环境变量后如果没有自动触发重新部署，去 Deployments 页手动 Redeploy 一下。
5. 需要国内访问的话，再把同一个仓库导入 Netlify，并把 `netlify.toml` 里转发的目标地址改成你自己的 Vercel 网址。

`resume-workflow/` 简历定制工具不在这个流程里——它不部署到 Vercel，是纯本地运行的工具，每个人要用都得在自己电脑上单独装 Python 依赖、配自己的 DeepSeek key、跑一遍 `register-protocol.ps1`，跟 fork/部署这个仓库是两件事。
