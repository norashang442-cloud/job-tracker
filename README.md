# 求职 / 申博进度追踪

两个独立的单文件追踪工具，分别服务秋招求职（`index.html`）和博士申请（`phd.html`）两条时间线。两者视觉风格一致、页面顶部互相有跳转链接，但数据、逻辑完全独立，互不影响——因为求职和申博的信息结构差异较大（前者是"公司→职位"的层级关系，后者是"导师↔项目"的多对多关系），硬塞进同一套数据模型只会让表单里堆满两边都用不上的字段。

## `index.html` · 秋招求职追踪

用来记录投递进度，按公司关注、具体职位、实际投递三个层级组织信息，方便回顾自己实际在关注哪些行业和岗位方向。

### 三层结构

一次求职决策通常要经历"知道公司→锁定职位→实际投递"这几个由模糊到明确的阶段，所以数据也拆成对应的三层，顶部导航栏按这个顺序排列并用箭头连接：**🏢 公司关注 › 📌 待投岗位 › 📋 投递追踪**：

- **🏢 公司关注**：只知道公司值得盯着，还没确定具体岗位。记公司名、行业、公告/官网链接、备注即可。公司卡片可以展开查看已经派生出的具体职位——不管这些职位是还在"待投岗位"阶段，还是已经进了"投递追踪"，都会一起显示（后者会带上真实的投递状态标签），方便一眼看出这家公司到底跟到哪一步了，避免同一家公司重复投递。列表按"🔍 待筛选"（还没有任何关联职位，默认展开）和"✅ 已有职位在跟进"（默认收起）分成两个折叠区块——已经派生出职位的公司说明筛选过了，不用再占注意力。
- **📌 待投岗位**：已经锁定的具体职位，尚未投递。每条记录标注：
  - 关注类型——**计划投递**（近期打算投）或 **长期关注**（感兴趣但暂不投，可选填原因，如能力/经验暂时不够、岗位尚未开放申请等）
  - 职位类型——全职/实习/应届生项目/科研/兼职/其他
  - 截止日期——支持标记**滚动招聘（Rolling Basis）**，即没有固定截止日期的岗位
  - 优先级、薪资、地点、可关联到已有的关注公司；默认按优先级排序
- **📋 投递追踪**：已经投出的申请，同样可以关联到关注公司。看板视图是按状态（已投递/已查看/面试中/已录用/已拒绝）分区的折叠式区块——有记录的默认展开、没有的收起成一行，避免"已投递"这类数量多的状态把页面拉得很长；区块内支持拖拽调整卡片顺序，跨区块拖拽（哪怕目标是收起状态）可以改变投递状态。每条记录可以记录完整的流程时间轴（笔试、面试、Offer Call 等环节及日期），每个环节能一键导出 `.ics` 日历文件（标题格式"公司-职位-环节"），导入手机日历后可以设提醒，间接实现截止日期提醒到手机。

不管在"待投岗位"还是"投递追踪"填公司名，输入时如果已有同名记录（不论在哪一层），都会实时提示"已有N条已投递/待投递记录"，提醒你可能要重复投了。

顶部统计栏显示总投递数、面试中、已录用、录用率。

数据存储在浏览器 `localStorage`（`jt4` 投递追踪 / `jt4_toApply` 待投递 / `jt4_companies` 公司关注），不上传到任何服务器，换浏览器或清缓存会丢失，建议定期用"导出"功能备份成 JSON 文件。

配套的 `api/extract.js` 是一个无状态的 Vercel Serverless Function，把粘贴的职位页面文字（或 URL）转发给 DeepSeek API，自动提取公司、职位、行业、职位类型、来源渠道，用于表单里的"自动填写"功能。需要在部署环境配置 `DEEPSEEK_API_KEY` 环境变量。

### `capture.html` · 手机端速记收件箱

解决"手机上刷到小红书/公众号的秋招/申博信息，没空仔细研究也不在电脑旁"的场景：`capture.html` 是一个极简的手机端网页（纯 HTML/JS，不加载 React，追求打开即用），顶部有"📋 秋招 / 🎓 申博"切换（记住上次选的），粘贴文字或帖子链接、点一下就存进对应的云端收件箱。

- 秋招那份收件箱回 `index.html`，点顶部导航栏的"📥 收件箱"（全局入口，任意 tab 下都能点），列表会自动跑一遍 `api/extract.js` 的 AI 提取、显示"推测：公司名 · 行业"，每条可以一键"转成关注公司"（如果内容里明确提到了官网/投递链接也会优先用那个而不是原始帖子链接）或者直接忽略。
- 申博那份收件箱回 `phd.html`，同样是顶部导航栏的全局"📥 收件箱"，用 `api/extract-phd.js` 提取，显示"推测：学校 · 项目"，每条可以"转成网申项目"或忽略。这边目前只支持转成网申项目，不支持转成套磁记录——套磁记录本来就基本是在电脑上直接录入的场景，没有额外做手机速记的必要。

这是整个项目里**唯一需要真正云端存储**的部分（其余数据都只在本机 `localStorage`），因为收件箱要在手机和电脑两端共享。技术上依赖：

- **Vercel KV**：在 Vercel 项目后台的 "Storage" 里创建一个 KV 数据库并关联到本项目，会自动注入 `KV_REST_API_URL` / `KV_REST_API_TOKEN` 这两个环境变量（`api/inbox-*.js` 三个函数都要用到）。
- **`INBOX_SECRET`**：自己设一个环境变量作为收件箱的访问密钥，防止别人拿到 `capture.html` 的链接后往你的收件箱里乱塞数据。手机端首次打开 `capture.html`、电脑端首次点开收件箱面板时都会各自要求输入一次这个密钥，之后存在本地不用再输；输错了可以在对应界面重新设置。两边用的是同一个密钥。

三个接口：`api/inbox-add.js`（写入，`capture.html` 调用）、`api/inbox-list.js`（电脑端拉取列表）、`api/inbox-delete.js`（转换或忽略后从收件箱移除）。三个接口都接受一个 `target` 参数（`job` 或 `phd`，默认 `job`），对应 KV 里两个独立的键（`inbox` / `inbox_phd`），秋招和申博的收件箱数据完全不会串。

**使用提示**：小红书这类 App 的"分享"按钮很多是自己定制的面板，不接入 iOS 系统分享，所以没法通过快捷指令（Shortcuts）自动投递到收件箱，只能靠 `capture.html` 手动复制粘贴。想让 AI 提取效果更好，尽量连**帖子文字**一起复制粘贴进去（而不是只存链接）——服务器抓取小红书链接本身大概率因为反爬/前端动态加载拿不到真实内容。图文帖（比如秋招汇总表格截图）建议只存帖子链接，回电脑自己点进去筛选，不做图片文字提取。

## `phd.html` · 博士申请追踪

用来记录套磁进度和网申项目进度，两者是多对多关系（一个导师可能关联多个网申项目，一个网申项目也可能关联多个联系过的导师），所以做成两个独立列表、互相关联，而不是像秋招那边那样做严格的层级结构：

- **🧑‍🏫 套磁记录**：导师姓名、所在院校、研究方向（自由填写，输入框会用浏览器原生的 datalist 自动检索你之前填过的方向做补全）、套磁进度（待发送→已发送→已回复→已约谈→成功/未成功）、沟通反馈时间轴（自由记录日期+内容，不设固定环节名称，因为套磁反馈内容因人而异）、可多选关联网申项目。
- **🎓 网申项目**：学校、项目/院系、申请批次、截止日期（同样支持标记**滚动招生**，即无固定截止日期）、网申状态（材料准备中→已提交→审核/面试中→已录取/Waitlist/未录取，Waitlist 单独列出是因为它和"未录取"是完全不同的状态）。卡片展开会反向显示关联的导师，不需要两头分别维护。表单同样支持"自动提取"——配套的 `api/extract-phd.js` 是专门为项目页面文字设计的提示词（提取学校/项目/批次/截止日期，跟 `api/extract.js` 面向职位JD的字段不一样），同样需要 `DEEPSEEK_API_KEY`。

数据存储在 `localStorage` 的 `phd_professors` / `phd_applications`，与秋招追踪器的存储完全独立，互不影响。目前还没有做研究计划模板库（相似方向导师共用的研究计划模板管理），后续视需要再加。

## 技术实现

- `index.html` / `phd.html` 是纯静态单文件：React 18 + Babel Standalone，均通过 CDN 引入，无需构建步骤，直接用浏览器打开即可运行，共享同一套视觉样式（配色、卡片、弹窗动效）。两个页面顶部各有一个跳转链接互相导航，但不共享任何数据。
- `capture.html` 是纯 vanilla HTML/JS，不引入任何框架，专门为手机端弱网/快速打开优化。
- 部署环境需要三个环境变量：`DEEPSEEK_API_KEY`（AI 提取）、`KV_REST_API_URL` + `KV_REST_API_TOKEN`（收件箱存储，随 Vercel KV 关联自动生成）、`INBOX_SECRET`（收件箱访问密钥，自己设定）。

## 使用

直接用浏览器打开 `index.html`（秋招）或 `phd.html`（申博）即可使用，两边头部都有链接可以互相跳转。自动提取功能、收件箱功能都需要项目部署在支持 Serverless Function 的平台（如 Vercel）才能生效，本地直接打开文件时会自动降级为手动填写/提示收件箱加载失败。数据的导入导出入口在 `index.html` 的"投递追踪"页顶部（`phd.html` 目前没有导入导出，数据全靠 localStorage 常驻）。

## 自己部署一份

代码里没有写死任何跟原作者账号绑定的东西，谁 fork 这个仓库都能部署出一套完全独立的实例，互不影响、不会用到别人的 API 额度或收件箱数据：

1. Fork 这个仓库到自己的 GitHub 账号。
2. 去 Vercel 导入这个仓库直接部署——零配置也能跑，只是 AI 提取和收件箱这两个功能会失效（其余全靠 localStorage 的功能完全不受影响）。
3. 想要完整功能，在自己 Vercel 项目的 Environment Variables 里配：
   - `DEEPSEEK_API_KEY`——自己去 DeepSeek 开发者平台申请
   - `KV_REST_API_URL` / `KV_REST_API_TOKEN`——在 Vercel 项目的 Storage 里关联一个 **Upstash for Redis** 数据库，这两个会自动生成，不用手填
   - `INBOX_SECRET`——自己定一串字符串，作为 `capture.html` 和收件箱面板的访问密钥
4. 改完环境变量后如果没有自动触发重新部署，去 Deployments 页手动 Redeploy 一下。
